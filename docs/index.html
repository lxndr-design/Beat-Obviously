Beat Documentation

One reference page for Beat workflows, instrument engines, plugin compatibility, user-guide material, and version history.

Version target: 0.2.0 pre-1.0, updated 2026-07-04.

Overview

Native Core

The C++ backend owns real-time audio, transport, sequencing, sampler playback, Aether rendering, Nodemap evaluation, file I/O, and project health verification.

Solid UI

The UI owns the timeline, editors, browsers, preferences, export review, plugin package views, and instrument editing. It uses the shared Solid UI kit and monochrome design tokens.

Projects

A new project starts in memory. Beat should only create or overwrite a project file when the user explicitly saves. Recent projects, backups, and health checks are part of the document workflow.

ActionExpected Behavior
New ProjectCreates an unsaved session. It should not silently write a file.
SaveIf no file exists yet, ask for a destination. Existing files save in place.
Save AsWrites a new project file and keeps the current session pointed at it.
OpenLoads tracks, instruments, plugins, audio references, automation, and project metadata.

Tracks and Timeline

Tracks can hold audio, MIDI, drum, mixed, or group content. Segment editing is free by default; holding Shift applies snap behavior.

  • Drag instruments, DS packages, components, or audio into tracks to create segments.
  • Drag segments freely; hold Shift to snap to the visible grid.
  • Resize and fade handles follow the same free-by-default, Shift-to-snap rule.
  • Track headers expose mute, solo, arm, input monitoring, volume, and meter display.
  • Playback highlights active segments and note previews through monochrome emphasis.

Aether Engine

Aether is Beat's native wavetable synth. It is the default path for Beat-created synth instruments.

Top Details

  • Name: patch name shown in the instrument library.
  • Category and Instrument: taxonomy fields used for organizing the library.
  • Voices: maximum polyphony before note stealing.
  • Legato: retunes held mono notes instead of retriggering fully.
  • Pitch Bend: MIDI bend range in semitones.
  • Velocity, Key Track, Mod Wheel: expression sources and routing state.

Nodemap Engine

Nodemap is a separate modular synth engine. It is not an Aether skin. A graph can be silent; sound only exists when audio reaches the protected Instrument Out node.

  • Every Nodemap has exactly one Instrument Out node.
  • Users cannot create or delete Instrument Out.
  • Audio ports connect to audio ports; control ports connect to compatible parameter inputs.
  • Multiple outputs can feed a compatible input only when that port explicitly supports it.
  • Disconnected nodes are allowed, but warnings explain that they do not affect sound.
  • Spacebar audition inside the Nodemap modal previews the instrument, not the global transport.

MIDI and Drum Editing

MIDI segments open in the piano roll. Drum segments open in the drum sequencer. Components/patterns are reusable musical blocks that can be previewed and dragged back to the arrangement.

  • MIDI notes should support create, drag, resize, select, copy, paste, delete, and context menu edits.
  • Beat patterns use segment speed consistently between list preview, editor preview, and arrangement playback.
  • Drum rows bind to real instruments where possible, not generic framework labels.
  • MIDI and drum segment previews in the track body should reflect note/hit placement, not placeholder bars.

Plugins and DecentSampler

Beat currently supports plugin-style instruments through safe import adapters. The supported path is DecentSampler package import plus a Beat sampler bridge. AU/VST3 live hosting is not enabled yet.

DecentSampler Workflow

  1. Open the DS rail tab or plugin import action.
  2. Choose a `.zip` or `.dspreset` file.
  3. Leave editor mode on Auto unless the package needs Drum or MIDI forced manually.
  4. Install from the native app so Beat can read files and register sample assets.
  5. Drag the installed DS package or created instanced instrument onto a track.
  6. Save the project so the plugin adapter, associated instrument id, and copied assets are persisted.
Browser preview can show lightweight package shells, but native app import is required for full ZIP extraction and reliable sample registration.

How To Make A Plugin

Until Beat has a public plugin SDK, a plugin should be built as a safe adapter around serializable project data, not as arbitrary code running in the audio callback.

  1. Choose the adapter format: usually native for internal Beat adapters or decent-sampler for DS packages.
  2. Define import data that can be saved in a `.beat` project without needing the original download folder.
  3. Register all audio assets with Beat's audio-file library or package sidecar.
  4. Create or link an associated Beat instrument if the adapter plays notes.
  5. Declare capabilities: instrument/effect/renderer/utility, realtime/offline support, latency, and fallback behavior.
  6. Add project-health validation for missing files, missing associated instruments, stale references, and unsupported runtime modes.
  7. Add a verifier or backend stress fixture that proves import, save/open, live playback, and export behavior.

Minimum Internal Checklist

  • Parser rejects unsafe paths and malformed packages.
  • Import copies or registers assets into Beat-managed storage.
  • Adapter state is serializable and document-roundtrip safe.
  • Project Health reports missing or broken dependencies.
  • Live playback and export agree, or the difference is documented.
  • The UI opens an adapter-specific editor instead of falling back to Aether unless explicitly intended.

Export

Export Review collects mode, destination, format, sample rate, bit depth, channel count, tail policy, and project-health validation before rendering.

  • Full Mix: render the project mix.
  • Review Range: render the selected loop/range.
  • Selected Stem: render one selected track/stem.
  • All Stems: render each renderable track as a batch.

Preferences

Preferences are grouped by left-side navigation. Expected groups are Audio, Files, Theme, AI, and advanced/system settings as needed.

Project Health

Project Health validates missing files, broken references, malformed sends, stale freeze metadata, plugin adapter links, and export blockers. Export should validate health before writing output unless the user explicitly disables that preference.
